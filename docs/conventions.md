# Правила репозитория

## Nix-стиль

- Максимально вертикально:

  ```nix
  {
    services = {
      foo = {
        enable = true;
      };
    };
  }
  ```

- `a.b = c` разворачивать в `a = { b = c; };`, если это не одна короткая
  настройка в большом списке.
- Списки — по элементу на строку, даже если элемент один.
- `imports` — в начале файла, по одному пути на строку, отсортированы.
- Атрибуты внутри одного уровня — по смыслу/алфавиту, без «красивых»
  выравниваний пробелами.
- Не оставлять пустые списки (`kernelModules = [ ];`) без причины.

## Файлы и каталоги

- Имя файла = предмет или корень опции: `qbittorrent.nix`, `resolved.nix`,
  `keyd.nix`. Не `services.nix`, `settings.nix`, `system.nix` внутри
  одноимённого каталога.
- `default.nix` — только hub с `imports`. Листья не импортируют листья.
- Один файл — одна ответственность. Если файл разрастается до 150+ строк и
  смешивает темы — делить.
- Домены: `hardware/`, `network/`, `security/`, `services/`, `programs/`,
  `desktop/`, `system/`, `packages/`, `users/`.
- Сторонний код — в `vendor/<name>/`, с лицензией и заметкой об upstream.
- Документация — в `docs/`; локальные README — только короткие указатели.

## Границы

- `common/` — переносимое; без `Michael`, `/home/Michael`, `/dev/nvme0n1`,
  sops-путей.
- `host/` — MagicBook; можно всё, что зависит от железа/пользователя.
- `host/identity.nix` — user/home/repoPath/hostName/diskDevice; для другой
  машины см. `docs/new-machine.md`.
- `iso/` — live; использует `common/` и `vendor/`, не тянет `host/`.
- `user/` — Home Manager; не знает, хост это или ISO.
- `host/home-manager.nix` — единственное место, где хост импортирует `user/`.
- `iso/home.nix` — единственное место, где ISO импортирует части `user/`.

## Комментарии

- Комментарий объясняет **почему**, а не что. Не пересказывать код.
- Неочевидные ограничения (keyd timeout, fstrim, Docker MTU, sphinx-hook,
  WARP, PAM/fprintd) — оставлять рядом с кодом.
- Не писать «temporary» без даты/причины; temporary-блоки должны иметь
  условие удаления.
- Не оставлять `enable = false` в импортируемом файле. Выключенное — в
  `docs/decisions.md` или в `parked/`, но не в живом дереве.

## Документация

- `docs/architecture.md` — карта и границы; обновлять при переименовании.
- `docs/ai.md` — контекст для агента; обновлять при изменении команд/путей.
- `docs/decisions.md` — почему что-то удалено/выключено.
- `docs/iso.md`, `docs/secrets.md`, `docs/manual-apps.md`, `docs/transfer.md` —
  по темам.
- Ссылки на темы памяти OpenCode (`topics/*.md`) в репозитории не работают:
  либо переносить факт в `docs/`, либо явно писать «память OpenCode».

## Проверка и коммиты

- Перед `nix eval` — `git add -A`: flake берёт только отслеживаемые файлы.
- Проверять все семь конфигураций, не только `MagicBook`.
- Не запускать `nixos-rebuild switch`, `disko`, `dd`, `sops updatekeys` без
  явной просьбы.
- Коммит — один понятный на задачу; тело — списком, что переименовано/удалено.
- Чекпоинт перед крупным рефактором — отдельный коммит, чтобы был откат.
