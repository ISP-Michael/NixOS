# Секреты: живые файлы + необязательный sops-снимок

## Главное

Живые секреты OpenCode/OpenClaw лежат в **настоящих файлах** с правами 0600:

```
~/.openclaw/openclaw.json
~/.local/share/opencode/auth.json
~/.local/state/opencode/service.json   (пароль)
```

Это источник истины. Приложение может писать, обновлять токены, создавать
файлы. Никаких read-only симлинков из Nix store.

`secrets/apps.yaml` — **необязательный** зашифрованный снимок этих файлов
для переноса/восстановления. Он не подключается к Nix и не влияет на живую
систему. Если не хочешь хранить даже зашифрованный снимок — не создавай его.

## .sops.yaml — что это

`.sops.yaml` — не хранилище секретов, а **политика шифрования**:

- какие публичные age-ключи могут расшифровывать `secrets/*.yaml`;
- какие пути к ним относятся.

Сами секреты — в `secrets/apps.yaml` в виде `ENC[AES256_GCM,...]`.
Приватные ключи в репозиторий не попадают.

## Как создать/обновить снимок

```bash
user/scripts/.config/apps/backup.sh
```

Скрипт читает живые файлы, пишет `secrets/apps.yaml`, шифрует его sops и
удаляет открытый текст. Секреты не печатаются. Если в старом снимке был
`telegram-bot-token`, он сохраняется (при возможности расшифровать архив).

## Как восстановить

```bash
user/scripts/.config/apps/restore.sh          # только отсутствующие
FORCE=1 user/scripts/.config/apps/restore.sh  # перезаписать, сделав .bak
```

Скрипт расшифровывает архив, кладёт `openclaw.json` и `auth.json` на места,
засеивает токен бота в secret store OpenClaw (если он не `REPLACE_ME`).
`service.json` целиком не перезаписывается: там runtime-поля pid/url.

## Смена ключа/подписки

1. Меняешь ключ в живом файле или через UI приложения.
2. Приложение сразу работает с новым ключом — **без пересборки**.
3. Если ведёшь снимок — запускаешь `backup.sh`; он перезапишет архив.
4. Старый архив можно удалить; в git попадёт только зашифрованная версия.

## Как это расшифровывается

- `sops` CLI использует твой admin age key (или host SSH key, если настроишь
  `SOPS_AGE_SSH_PRIVATE_KEY_FILE`).
- `sops-nix` для системных секретов (`secrets/secrets.yaml`) расшифровывает
  host-ключом `/etc/ssh/ssh_host_ed25519_key` при активации; это отдельный
  механизм и к `apps.yaml` не применяется.
- Явный `--config /etc/nixos/.sops.yaml` нужен потому, что автопоиск
  `.sops.yaml` от пути файла в этой среде не сработал.

## Перенос на другую машину

1. Скопировать флейк и `secrets/apps.yaml` (если он есть).
2. Добавить публичный ключ новой машины в `.sops.yaml` (age или SSH host key
   через `ssh-to-age`).
3. `sops updatekeys secrets/apps.yaml` (или перешифровать).
4. Установить приложения, выполнить `install.sh`, затем `restore.sh`.
5. Заполнить `telegram-bot-token`, если он `REPLACE_ME`.

## Это нормально без Nix?

Да. `sops` — самостоятельный инструмент; его можно использовать с любыми
скриптами. `sops-nix` — удобная интеграция для системных секретов NixOS, но
не обязательное условие. Плохая практика — plaintext-секреты в git или
в Nix store; зашифрованный снимок + живые 0600-файлы — нормально.
